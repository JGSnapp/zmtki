# Итерация 3 — блоки до конца: Google Chrome, стрим приложений, файлы

**Запрос (2026-09-16):**
1. иконка в заголовке и на панели задач — не присланная Z;
2. блок при перетаскивании улетает в левый верхний угол;
3. инерция блоков работает неправильно;
4. доделать блоки, в том числе стрим приложений; браузер — настоящий Google Chrome, а не самодельный.

## Исправления

| Проблема | Причина | Исправление |
| --- | --- | --- |
| Иконка Electron вместо Z | Файла не было на диске; Windows группировала окно под `electron.exe` | `resources/icon.png` (присланный) → `scripts/build-icons.cjs` собирает `icon.ico` 16–256 px; окно берёт .ico, у приложения свой AppUserModelId |
| Блок улетает в угол | Нажатие выделяло карточку браузера, её `<webview>` в другом процессе забирал указатель → `pointercancel` с координатами (0, 0), по ним считалась итоговая позиция | При отмене — последняя реальная позиция указателя; во время любого жеста с карточкой встроенные страницы и видео не принимают указатель; нативное перетаскивание ссылок и картинок в карточках отключено |
| Инерция блоков | Доводка до сетки после броска шла 260–620 мс ease-in-out и начиналась с позиции прошлой анимации, если карточку подхватили на лету | Доводка — 160 мс с замедлением ровно от точки отпускания; захват останавливает незаконченную анимацию; инерция доски — только после явного рывка (> 0,35 px/мс) |
| Пустое окно при зуме (найдено тестом) | Блоки рисовались вызовом функции: хуки блока становились хуками карточки, и переход «упрощённо ↔ детально» менял их число — React #310 ронял всё дерево | Блоки рисуются как компоненты |

## Блоки

### Браузер — Google Chrome
- Карточка — вкладка **установленного Google Chrome** (новый headless-режим: тот же браузер без
  своего окна), связь по DevTools Protocol
- Страница приходит кадрами скринкаста в `<canvas>`; мышь, колесо, клавиатура, Ctrl+C / Ctrl+V
  уходят обратно в Chrome
- Кадр подтверждается только после отрисовки — страница не может завалить доску кадрами;
  кадры идут только пока карточка на экране
- Вкладка живёт в размере карточки, плотность пикселей следует зуму доски — текст чёткий
- По умолчанию открывается Google; адресная строка понимает адрес, домен или поисковый запрос
- Назад/вперёд/обновить, «Открыть в Chrome» — страница в обычном окне Chrome
- Всплывающие окна открываются в той же карточке, диалоги страницы не вешают её
- Адрес страницы сохраняется в карточке (вне undo); агент меняет `props.url` — вкладка переходит
- Профиль Chrome — отдельный, в папке данных приложения: вход в аккаунты сохраняется между
  запусками и не конфликтует с личным Chrome
- Если Chrome не установлен — карточка говорит об этом (`ZMTKI_CHROME` — путь вручную)

### Стрим приложения
- Выбор окна или экрана по миниатюрам (desktopCapturer), живое видео до 30 к/с
- Захват держится только пока карточку видно
- После перезапуска окно находится заново по названию
- «Перейти к окну» выводит приложение на передний план

### Редакторы — настоящие файлы
- `code-editor`, `text-editor`, `markdown-doc` — CodeMirror 6: подсветка, нумерация, поиск,
  автоотступы
- Файл с диска: Ctrl+S / «Сохранить» (атомарная запись), индикатор несохранённого,
  изменение файла снаружи подхватывается при возврате в окно или предлагается загрузить
- Markdown-документ: «Просмотр» / «Править»
- Без файла текст хранится в карточке и сохраняется при уходе с неё

### Остальное
- **Код** — подсветка highlight.js (15 языков, автоопределение)
- **Изображение, видео, аудио** — ссылка или файл с диска (протокол `zmtki-file://`), выбор файла
- **Файл** — размер и дата с диска, «Открыть» программой по умолчанию, «В папке», двойной клик
- **Канбан** — правка карточек и названий колонок двойным кликом, удаление, новые колонки,
  перенос карточек между колонками и внутри
- **Кнопка** — ссылка или команда в выбранный терминал
- **Файлы из проводника** на доску становятся блоками по типу: картинка, видео, аудио, markdown,
  редактор кода, текстовый редактор или карточка файла
- **Панель «Свойства»** для выделенного блока: цвет заметки, типографика текста, форма и цвета
  фигуры, язык и код, действие кнопки, цвет и толщина рисунка, источники медиа, адреса, HTML,
  файлы редакторов

## Проверка

- **155 юнит-тестов**
- **`npm run e2e` — 23 проверки анимаций и жестов**, среди новых: `pointercancel` посреди
  перетаскивания оставляет карточку на месте
- **`npm run e2e:blocks` — 14 проверок в живом окне:** Chrome присылает кадры, открывает Google,
  кадр — отрисованная страница, адресная строка переходит, карточка помнит страницу, клик
  фокусирует страницу, перетаскиваемая карточка браузера идёт за указателем (+160/+100 при
  рывке +160/+90 со снапом к сетке); стрим перечисляет окна и экраны и играет; редактор
  показывает файл с диска, Ctrl+S пишет правку в файл; изображение грузится с диска; карточка
  файла показывает размер и дату
- **Бенч 5 000:** 59,0 FPS, p95 16,8 мс — без регрессии

## Известные ограничения

- Стрим приложения — только просмотр. Чтобы работать в программе, «Перейти к окну»
  переключает на неё
- Курсор над страницей Chrome не меняет форму (рука над ссылкой и т.п.)
- Ввод через IME со сложной композицией (китайский, японский) в Chrome-карточке не проверялся;
  русская и английская раскладки работают
- Загрузки файлов из Chrome-карточки пока не настроены
- «Меню приложений» Windows (Пуск) покажет Z только у собранного установщика — в dev-режиме
  приложение там не зарегистрировано; в заголовке окна, на панели задач и в Alt+Tab — Z
