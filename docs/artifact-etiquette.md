# Артефактный этикет

Доска — отчёт и рабочее пространство агента. Человек должен видеть ход работы в реальном времени и читать пространство как структурированную «доску расследования».

**Живой источник правды** — настройки приложения → вкладка **«Артефактный этикет»**.  
Каждый пункт можно включить, выключить, отредактировать, удалить или добавить.  
Включённые правила форматируются в системный промпт агента (`formatArtifactEtiquette` → `buildPromptTiers`).

Заводской набор (ниже) совпадает с `DEFAULT_ARTIFACT_ETIQUETTE` в `packages/core/src/app/settings.ts`.

## Заводские правила

1. **Прозрачность действий (Traceability)**  
   Сначала создай артефакт (terminal, browser и т.п.), затем запускай процесс. Пользователь должен видеть работу в реальном времени, а не только финальный результат.

2. **Максимальная декомпозиция (Decomposition)**  
   Выбирай kind строго под суть подзадачи и дроби работу. Вместо одного огромного markdown или file раскладывай задачу на набор fileFragment, todo, terminal, chart и других узлов внутри рамки — если явно не попросили иное.

3. **Семантический формат (Semantic Medium)**  
   Никаких простыней текста. Код — diff / fileFragment; архитектура — mermaid; данные — chart / table; задачи — kanban / todo; интерфейсы — htmlWidget / demo; короткий пульс — status.

4. **Эстетика «доски детектива» (Aesthetics)**  
   Оформляй пространство структурно: выравнивай (`board_arrange` / `board_place`), не допускай наложений, компонуй вокруг смысловых центров. Со стрелками — больше воздуха и `layout=flow`.

5. **Обязательная связность (Topology)**  
   Соединяй зависимые артефакты (`board_connect`). Фиксишь баг — стрелка от лога/ошибки к фрагменту кода. После нескольких связей — `board_arrange layout=flow` (минимум пересечений).

5a. **Чистые связи (Edge Clarity)**  
   Не оставляй схемы «клубком»: поток, отступы, `flow`-раскладка вместо ручных пикселей.

6. **Текстовое сопровождение (Context Notes)**  
   Не оставляй узлы немыми: рядом — стикер (`sticker_place`) или короткий markdown с пояснением «зачем / что происходит / вывод».

7. **Локальность и группировка (Grouping)**  
   Артефакты одной задачи — компактно и в `board_group` с accent, чтобы двигать блоком.

8. **Чистота и свёртывание (Lifecycle)**  
   Завершил подзадачу — `board_set_state` (widget/icon/ghost) или `board_delete` для временного мусора.

9. **Фокус вместо дублирования (No Duplication)**  
   Сначала `board_search` / `search_files` / `board_read`. Уже есть на доске — не копируй; двигай рамку (`board_move_frame` / `board_focus`) и обновляй.

10. **Уважение к чужому (Non-Destructive)**  
    Не трогай lock / человеческие объекты без разрешения; предложи через стикер или `board_comment_reply`.

11. **Пространственное делегирование (Portals)**  
    Чужому агенту — `portal_create` + комната (`@mention` / `task_assign`), без копирования файлов на свою доску.

12. **Информационная плотность (Signal)**  
    Не оставляй бессодержательные узлы без факта, вывода или следующего шага — сверни или удали.

13. **По этапу задачи (Just-in-time)**  
    Status / kanban / todo — не сходу «на всякий случай», а когда этап задачи реально этого требует.
