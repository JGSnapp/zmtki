# Справочник видов артефактов

Каждый `kind` из схемы доски: зачем нужен, когда создавать, когда обновлять, когда не создавать.

См. также [artifact-etiquette.md](./artifact-etiquette.md).

## terminal

- **Зачем:** живой вывод команды.
- **Создавать:** обычно не вручную — `shell` / связанные tools создают сами.
- **Обновлять:** через жизненный цикл процесса (running → exit).
- **Не создавать:** второй терминал на ту же команду «для отчёта»; не копируй вывод в `markdown`.

## browser

- **Зачем:** живая веб-страница / проверка UI.
- **Создавать:** когда нужно смотреть страницу на доске, а не только URL в чате.
- **Обновлять:** URL / live-флаг.
- **Не создавать:** если достаточно `link` или `demo`.

## file

- **Зачем:** снимок файла целиком (превью).
- **Создавать:** когда файл — центральный объект обсуждения.
- **Обновлять:** при существенном изменении содержимого.
- **Не создавать:** вместо диффа правки; для куска кода лучше `fileFragment`; не вместо вики/обзора (это `markdown`).

## fileFragment

- **Зачем:** важный фрагмент кода с номерами строк.
- **Создавать:** чтобы указать на конкретное место («смотри вот это»), максимум 1–2 к hero-документу.
- **Обновлять:** если фрагмент устарел после правок.
- **Не создавать:** на каждый прочитанный файл; не дублируй весь файл; не собирай «вики» из одних фрагментов.

## diff

- **Зачем:** показать правку.
- **Создавать:** обычно автоматически при записи файла.
- **Обновлять:** редко; новый патч — новый смысл, чаще новый узел или обновление того же.
- **Не создавать:** вручную «отчёт о том, что уже показал write_file».

## markdown

- **Зачем:** заметка, спецификация, вики, обзор проекта, инструкция «что и как делать».
- **Создавать:** когда нужен читаемый текст на доске; для вики — один развёрнутый документ (цель, структура, команды, потоки, как постить/обновлять).
- **Обновлять:** держи один живой документ по теме.
- **Не создавать:** ради одного предложения — это чат; не для дашбордов (лучше `htmlWidget` / `chart`).

## image

- **Зачем:** скриншот, схема-картинка, референс.
- **Создавать:** когда визуал важнее текста.
- **Обновлять:** замени source при новом скрине.
- **Не создавать:** декоративные заглушки без содержания.

## table

- **Зачем:** сравнение, результаты поиска, метрики списком.
- **Создавать:** когда столбцы помогают сравнить строки.
- **Обновлять:** тот же узел при новых данных.
- **Не создавать:** сырой dump без заголовков; одно значение — `status.fields`.

## kanban

- **Зачем:** план и прогресс по колонкам.
- **Создавать:** в начале задачи — один на рамку.
- **Обновлять:** двигай карточки по ходу.
- **Не создавать:** второй канбан «для другого взгляда»; не вместе с полным дублем `todo` на ту же работу (выбери одно).

## status

- **Зачем:** пульс «что сейчас / чем кончилось».
- **Создавать:** один на задачу в начале или при первом осмысленном шаге.
- **Обновлять:** постоянно (headline, detail, progress, tone, fields).
- **Не создавать:** новый status на каждый шаг.

## todo

- **Зачем:** простой чеклист.
- **Создавать:** вместо kanban, если задача линейная и короткая.
- **Обновлять:** отмечай done.
- **Не создавать:** параллельно с kanban на ту же задачу.

## mermaid

- **Зачем:** архитектура, поток, зависимости.
- **Создавать:** когда схема объясняет лучше абзаца.
- **Обновлять:** тот же узел при изменении схемы.
- **Не создавать:** тривиальные 2-узловые диаграммы «ради вида».

## chart

- **Зачем:** числовые ряды, доли.
- **Создавать:** когда тренд/доля важны визуально.
- **Обновлять:** данные на месте.
- **Не создавать:** для 2–3 чисел — хватит `status` или `table`.

## link

- **Зачем:** внешняя ссылка с пояснением.
- **Создавать:** важный URL, к которому будут возвращаться.
- **Обновлять:** title/description.
- **Не создавать:** каждую ссылку из поиска (лучше одна `table` источников).

## htmlWidget

- **Зачем:** произвольная вёрстка, когда нет подходящего kind.
- **Создавать:** только если table/chart/mermaid/markdown/controls не закрывают задачу.
- **Обновлять:** html на месте.
- **Интерактив:** элементы с `data-zmtki-action` шлют `artifact.control` в core.
- **Не создавать:** для обычного текста или простого списка.

## controls

- **Зачем:** дашборд кнопок, тогглов, слайдеров, полей для управления проектом с плоскости.
- **Создавать:** когда человеку нужны интерактивные рычаги без чата.
- **Обновлять:** values через `board_update_artifact` / события control.
- **Не создавать:** вместо одного статуса или markdown-инструкции.

## demo

- **Зачем:** запущенное приложение / URL демо с командой запуска.
- **Создавать:** как hero-итог, когда есть что открыть.
- **Обновлять:** running / url / command.
- **Не создавать:** до того, как демо реально доступно.

## portal

- **Зачем:** снимок артефакта с другой доски.
- **Создавать:** когда нужен явный мост между проектами.
- **Обновлять:** snapshot при устаревании.
- **Не создавать:** вместо просьбы агенту-резиденту чужой доски что-то сделать.
