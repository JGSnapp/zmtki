# Artifact Board

Мультиагентная доска для разработки. Каждая доска — это папка на диске, каждый агент — рамка
на доске, а всё, что агент делает, он показывает **артефактами**: окнами терминала, диффами,
браузером, канбан-досками, схемами, дашбордами, произвольными HTML-виджетами.

## Чем это отличается от чата с ассистентом

В чате результат работы — текст, который надо читать сверху вниз. Здесь результат —
пространство: терминал крутится в одном углу, диф правки лежит рядом с файлом, статус задачи
висит на канбане, а рядом схема архитектуры. Работу нескольких агентов видно одновременно,
потому что у каждого своё место на доске, а не своя очередь в ленте.

## Запуск

```bash
pnpm install
pnpm dev
```

Дальше в приложении: `+` в левом рельсе создаёт доску (выберите пустую папку), затем
`+ агент` на верхней панели. Перед первым ходом откройте настройки (`⚙`) и добавьте
эндпоинт LLM — есть пресеты для OpenAI, Anthropic, OpenRouter, Groq, DeepSeek и локальной
Ollama. Ключи шифруются средствами ОС (DPAPI/Keychain) и остаются на вашей машине.

Другие команды:

```bash
pnpm build       # продакшн-сборка
pnpm dist        # установщик через electron-builder
pnpm typecheck   # строгая проверка типов по всем пакетам
pnpm smoke       # сквозные проверки ядра без Electron
pnpm check       # typecheck + lint + smoke
```

`pnpm smoke` прогоняет два сценария. `scripts/smoke.mjs` проверяет доску, рамки,
комнаты и комментарии. `scripts/agent-smoke.mjs` поднимает на localhost сервер,
говорящий в формате стриминга OpenAI, и гоняет через него настоящий ход агента:
сообщение в комнату, вызов инструмента, артефакт внутри рамки, ответ в чат. Ключ
для этого не нужен, и поведение детерминированное, чего не дала бы живая модель.

## Структура

```
packages/board-schema   zod-схемы доски, узлов, артефактов, агентов; формат папки доски
packages/protocol       типизированные Op (UI -> ядро) и EventMsg (ядро -> UI)
packages/core           всё ядро: доска, агенты, комнаты, LLM, поиск, инструменты
apps/desktop            Electron: main-процесс, preload-мост, React-рендерер
```

### Папка доски

```
my-board/
  board.zmtki.json          документ доски: узлы, связи, слои, камера
  .zmtki/
    agents.json             агенты этой доски
    comments.json           треды комментариев
    board.outline.md        текстовый слепок доски, читаемый человеком и git
    artifacts/<nodeId>/     тяжёлые payload-ы: картинки, скроллбэки, большие виджеты
    rollouts/<agentId>.jsonl история ходов агента
```

Разделение осознанное: `board.zmtki.json` остаётся маленьким и диффится в git, а всё
объёмное лежит рядом файлами. Ключи сортируются детерминированно, поэтому мердж-конфликты
в доске — это конфликты по смыслу, а не по порядку полей.

Всё, что относится к проекту, лежит в его папке. Всё, что живёт поверх проектов — реестр
агентов, комнаты, уведомления, очереди — в `~/.zmtki/app.db`, потому что группа может
состоять из агентов разных досок.

## Как устроена многоагентность

**Рамка как контекст.** Всё, что геометрически внутри рамки агента, он держит в контексте
целиком. Остальную доску видит компактным индексом: заголовок, тип, одна строка описания.
Инструментом `board_move_frame` агент двигает рамку и тем самым меняет то, что видит — это
единственный способ управления контекстом, который не требует объяснять модели, что такое
контекст.

**Комнаты.** Личка, группы и канал проекта — одна сущность с разным составом участников.
Порядок ответов задаётся политикой комнаты, а не просьбой в промпте:

| Политика | Кто отвечает |
| --- | --- |
| `mention-only` | только тот, кого позвали через `@`. Умолчание для групп |
| `moderated` | слово раздаёт модератор через `room_yield` |
| `round-robin` | по кругу |
| `free` | все сразу. Умолчание только для лички, где зацикливаться не с кем |

**Предохранители.** Каждое сообщение несёт цепочку причинности до сообщения человека,
с которого всё началось. Превышен лимит прыжков агент→агенту — комната встаёт на паузу.
Агенты обмениваются репликами, не трогая доску, — детектор застоя останавливает разговор.
Кончился бюджет токенов или денег — тоже пауза. Любое сообщение человека снимает паузу,
потому что предохранители защищают от разогнавшихся агентов, а не от владельца проекта.

**Очередь входящих.** Упоминания складываются в durable-очередь в SQLite и разбираются
дайджестом в начале следующего хода агента. Поэтому три сообщения подряд дают один ход,
а не три, и ничего не теряется, если приложение закрыли.

**Планировщик.** Глобальный лимит одновременных ходов на все открытые проекты. Пять
проектов по три агента иначе радостно запустят пятнадцать ходов и высадят и машину, и
бюджет API.

## Артефакты

Реестр `kind -> React-компонент`, поэтому новый вид артефакта добавляется одним файлом.
Сейчас есть: `terminal`, `browser`, `file`, `fileFragment`, `diff`, `markdown`, `image`,
`table`, `kanban`, `status`, `todo`, `mermaid`, `chart`, `link`, `htmlWidget`, `demo`,
`portal`.

Два из них стоит отметить отдельно:

- **`browser`** — настоящее окно браузера (Electron `WebContentsView`), а не iframe:
  большинство сайтов запрещают встраивание. Плата за это — вид рендерится поверх холста,
  поэтому рендерер шлёт его экранный прямоугольник при каждом движении камеры, а на
  сильном отдалении вид прячется и заменяется постером.
- **`htmlWidget`** — то, что делает фразу «агент может показать что угодно» правдой.
  HTML исполняется в iframe с `allow-scripts`, но без `allow-same-origin`: свой код
  работает, до приложения и preload-моста не дотягивается.

На любой артефакт можно оставить комментарий, как в Google Docs. `@агент` в комментарии
кладёт тред в его следующий ход; без упоминания комментарий уходит автору артефакта.

## Ядро

**BoardStore** — Yjs поверх папки доски. CRDT нужен не для сети, а потому что человек
двигает узлы мышкой ровно тогда, когда агент создаёт новый: без сходимости пришлось бы
блокировать доску на время хода. `Y.UndoManager` с `trackedOrigins` позволяет человеку
отменять свои действия, не задевая правки агентов.

**AgentRuntime** — цикл `runTurn`: собрать контекст, вызвать модель, исполнить инструменты,
повторить. Read-only инструменты идут параллельно, мутирующие — последовательно.
Сообщение человека во время хода не встаёт в очередь, а вклинивается через `steer`, иначе
«стоп, не туда» подействовало бы после того, как не туда уже сделано.

**Промпты** — три уровня: `stable` (протокол артефактов, правила, персона), `context`
(содержимое рамки, индекс доски, ростер агентов), `volatile` (сообщение и очередь).
Граница после `stable` помечена как точка кэша, поэтому провайдеры с prefix-кэшем не
пересчитывают неизменную часть каждый ход.

**LLM** — провайдер определяется по хосту, payload собирается под формат конкретного API
(OpenAI, Anthropic, Ollama, Google), плюс цепочки фоллбэка. Стриминг, tool calling и
vision работают одинаково независимо от провайдера.

**Поиск** — SearXNG, Brave, DuckDuckGo, Google PSE, Tavily, Serper с фоллбэком.
Веб-фетчер защищён от SSRF: хост резолвится в IP, приватные и зарезервированные диапазоны
отсекаются, запрос идёт на проверенный адрес с сохранением имени для TLS, объём ответа
ограничен.

## Навигация

| Клавиши | Действие |
| --- | --- |
| `Ctrl+K` | палитра команд: агенты, артефакты, чаты, проекты |
| `Alt+1..9` | перейти к рамке n-го агента |
| `V H S T R O D A P F C` | инструменты |
| `Ctrl+Z` / `Ctrl+Shift+Z` | отменить / повторить |
| `Backspace` без выделения | вернуть камеру назад |

Двойной клик по чипу агента включает follow mode: камера едет за агентом, но только когда
он что-то создаёт, а не на каждое движение.

## Статус

Ядро, доска, артефакты, комнаты и многоагентность собраны и проходят `pnpm check`.
Полный цикл хода агента — от сообщения до артефакта на доске — проверен на локальном
фейковом провайдере.

Не сделано: `node-pty` вместо `child_process` для интерактивных TTY, Monaco вместо
подсветки-заглушки в файловых артефактах, CDP-доступ агента к browser-артефакту,
split view для двух досок одновременно.

Не проверено вживую: ход на настоящей модели (нужен ключ, форматы стриминга
Anthropic, Google и Ollama написаны по документации, но по сети не гонялись), и UI
под нагрузкой в несколько сотен узлов.
